# 离线相册与 Activity 优化方案

日期：2026-10-05。基线：`main` / `v0.8.0` / `5ed5b88`。

## 目标与范围

本轮优先解决离线相册编辑容易丢失修改、配置说明偏技术化，以及 Activity
状态难以理解和待处理内容难以定位的问题。保持紧凑的原生界面，复用现有
Companion API。Library 搜索和 Lineup 复制留作后续独立功能。

## 实施顺序

1. 将 Lineup 已验证的退出保护整理成通用草稿保护组件，保持现有行为和
   iOS 18 / CI Xcode 工具链兼容。
2. 离线相册接入保护：未修改直接退出；修改后 Cancel 或下滑必须明确选择
   保留或丢弃；检查、保存和删除期间禁止退出。图片排序改动直接保留在父级
   草稿中，子页面返回不丢排序，只有最终 Save 才提交服务端。
3. 离线相册按实际保存语义比较草稿，忽略名称两端空格和设备选择顺序。
   保留服务器预检查、冲突确认和不支持设备限制；将协议与实现说明改成简短
   的操作说明，同步英文与简体中文。
4. 核对服务端 Activity / Job 状态含义，改进用户可见标签和必要说明。
   服务端接收、请求刷新和设备已刷新严格区分，未知状态保守展示。
5. Activity 提供 All / Needs Attention 筛选。待重试本地请求和失败任务可见；
   正常排队、静默时段、被新请求替代、去重等不因状态名称而误判为失败。
   保持历史分页和现有去重，筛选无结果时明确说明当前已加载记录的范围。

## 验收

- 相册：新建与编辑的无修改退出、改后还原、保留/丢弃、排序子页下滑、
  Review 返回、失败后草稿保留、保存期间退出限制。
- Activity：已知状态语义与失败分类测试，混合成功/失败和未知状态，筛选
  切换、空结果、历史继续加载；不能把无匹配记录说成全局没有问题。
- 回归 Lineup 的现有退出保护，确认公共组件调整不改变原有交互。
- 单元测试、定向 UI 测试、模拟器构建；浅色/深色和大字号截图检查。
- 更新 CHANGELOG Unreleased。真机 BLE / 墨水屏状态确认单独记录，不能用
  模拟器通过代替硬件验证。
